# Polylane Provider

[Polylane](https://polylane.com) helps teams investigate and resolve production issues. Use the Polylane provider to manage the workspace, access, cloud connections, and operational settings that support your team.

Define configuration in code, review changes in a Terraform plan, and apply them alongside the rest of your infrastructure.

[Polylane documentation](https://docs.polylane.com) · [Polylane console](https://console.polylane.com) · [Source code and issues](https://github.com/coreplanelabs/terraform-provider-polylane)

## Get started

You need Terraform 1.6 or later, an existing Polylane workspace, and a workspace API key. Create a key in your workspace's **Settings → API keys** and grant the scopes required by the resources you plan to manage. See [Authentication](guides/authentication.md).

Supply the key through your shell or CI secret manager as `POLYLANE_API_KEY`. The provider uses `https://api.polylane.com/v1` by default.

### Install the provider

```terraform
terraform {
  required_version = ">= 1.6.0"

  required_providers {
    polylane = {
      source  = "registry.terraform.io/coreplanelabs/polylane"
      version = "~> 0.1.0"
    }
  }
}

provider "polylane" {
  # Prefer POLYLANE_API_KEY so the key is not written in configuration.
}
```

### Import your workspace

Add the following to your configuration, replacing the example ID with your workspace's `ws_…` ID:

```terraform
resource "polylane_workspace" "current" {
  # Workspaces are adopted by import. Add name, slug, description, or
  # auto_join only when Terraform should manage that property.
}

import {
  to = polylane_workspace.current
  id = "ws_00000000000000000000000000000000"
}
```

Run `terraform init`, then `terraform plan` to review the import. Run `terraform apply` to bring the workspace into Terraform state. This initial configuration adopts the existing workspace without changing its properties.

See [Manage an existing workspace](guides/manage-workspace.md) for the next steps.

## Understand resource ownership

Workspace and workspace-member resources adopt existing objects. Removing them from Terraform configuration stops Terraform management without deleting those objects. Removing workspace settings resources leaves their current settings in place.

Teams, team memberships, and AWS connection requests have a managed lifecycle: removing them from configuration deletes the corresponding Polylane objects. Removing an AWS connection deregisters it from Polylane.

AWS infrastructure stays under your control. Use the AWS provider to manage IAM roles, CloudTrail, S3, and SNS; the Polylane provider manages only the connection to Polylane. It does not use AWS credentials or delete your AWS infrastructure.

## Provider configuration

Explicit provider arguments take precedence over their environment variables. Prefer environment variables for credentials. For a non-default environment, set `POLYLANE_ENDPOINT` to its API base URL, including `/v1`.
